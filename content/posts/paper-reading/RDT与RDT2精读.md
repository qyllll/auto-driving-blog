## 小白篇：先搞懂"扩散模型用在机器人上"到底在干什么

> 如果你对扩散模型和机器人的交叉不熟，先读这里。

### 扩散模型不只是画图的

大多数人对扩散模型的印象是"画图"——从噪声一步步去噪生成图片。但扩散模型的本质是：

> **从一个混乱的起点，一步步"整形"成目标形状。**

这个"形状"可以是图片，也可以是**一条机器人动作轨迹**。

```
画图：  纯噪声 → 逐步去噪 → 一张图片
机器人：随机动作轨迹 → 逐步去噪 → 一条合理的动作轨迹
```

这就是 RDT（Robotics Diffusion Transformer）的核心思想：**用扩散模型生成机器人动作**。

### 为什么机器人需要扩散模型？

机器人动作有两个特点，让传统方法很难处理：

**特点一：多模态（同一个任务可能有多种正确做法）**

```
"把杯子放到架子上" 这个任务：
  做法 A：从左边绕过去拿
  做法 B：从右边绕过去拿
  做法 C：直接伸过去拿
  → 三种都对！动作分布是"多峰"的
```

传统回归模型（如 ACT）会把三种做法"平均"成一条轨迹——结果是一条谁都不像的"鬼影"轨迹。

扩散模型天然擅长建模多模态分布——它可以在采样时"选择"其中一个模式，生成一条清晰、合理的轨迹。

**特点二：双臂协调更复杂**

```
单臂：1 个末端执行器 → 动作空间 ~7 维
双臂：2 个末端执行器 → 动作空间 ~14 维
  → 两只手要协调（一只手拿杯子，另一只手拧盖子）
  → 动作分布更复杂，多模态更明显
```

这就是为什么 RDT 选择扩散模型——它是目前**唯一能同时解决多模态和高维动作**的生成方法。

## RDT-1B：第一个机器人扩散基础模型

### 要解决什么问题？

双臂机器人操作面临两大难题：

1. **数据稀缺**：特定机器人的数据极少（不像互联网有海量图片/文字）
2. **多模态动作分布**：两只手协调时，同一个任务有多种正确做法

现有方法的困境：

| 方法 | 做法 | 问题 |
|------|------|------|
| ACT（回归） | 直接回归动作均值 | 多模态时"平均"成鬼影轨迹 |
| Octo（离散化） | 把连续动作离散成 token | 精度损失，丢失连续性 |
| OpenVLA（VLA） | 用 LLM 预测离散动作 token | 动作空间受限，不适用高维双臂 |

RDT 的解法：**用扩散模型建模动作分布 + 用 Transformer 做可扩展的骨干网络**。

### 整体架构：DiT + 多模态编码

```
输入：
  RGB 图像（3 个视角）→ SigLIP 编码器 → 图像 token
  语言指令 → T5-XXL 编码器 → 文本 token
  本体感知（关节角度等）→ MLP + Fourier → 状态 token
      ↓
  融合编码 → DiT（28 层，1.2B 参数）
      ↓
  去噪过程：从随机噪声 → 逐步预测 → 输出 64 步动作轨迹
      ↓
输出：a₁, a₂, ..., a₆₄（未来 64 步的动作）
```

### 扩散模型在 RDT 中怎么工作？——逐公式拆解

#### 训练时：给动作加噪声，学着去噪

RDT 用的是标准 DDPM（Denoising Diffusion Probabilistic Model）：

**第一步：加噪（前向过程）**

$$a_t^k = \sqrt{\bar\alpha^k} \cdot a_t^0 + \sqrt{1 - \bar\alpha^k} \cdot \varepsilon$$

翻译成人话：
- $a_t^0$：真实的动作轨迹（64 步 × 维度）
- $\varepsilon \sim \mathcal{N}(0, I)$：随机噪声
- $k$：当前加噪到第几步（从 1 到 1000）
- $\bar\alpha^k$：噪声调度参数，随 $k$ 增大而减小
- $a_t^k$：加噪后的动作轨迹

直觉：$k$ 小 → 噪声少，动作还比较清晰；$k$ 大 → 噪声多，动作接近纯噪声。

**第二步：训练网络预测噪声**

$$\mathcal{L} = \mathbb{E}\Big[\big\| \varepsilon - f_\theta(\ell, o_t, a_t^k, k) \big\|^2\Big]$$

翻译：
- $f_\theta$：RDT 网络（DiT），输入是语言 $\ell$、观测 $o_t$、加噪动作 $a_t^k$、时间步 $k$
- 输出：预测的噪声 $\hat\varepsilon$
- 正确答案：真实的噪声 $\varepsilon$
- Loss：MSE（预测噪声 vs 真实噪声）

**训练目标**：让网络学会"从带噪动作中识别出噪声"。训练完后，它就能从纯噪声中一步步去噪，生成合理动作。

#### 推理时：从噪声出发，5 步去噪

```
第 0 步：aₜ⁵ = 随机噪声 ~ N(0, I)     （完全随机的轨迹）
第 1 步：aₜ⁴ = 去噪一步（网络预测噪声，减掉）  （开始有点像轨迹了）
第 2 步：aₜ³ = 去噪一步                   （更像轨迹了）
第 3 步：aₜ² = 去噪一步                   （几乎是一条轨迹了）
第 4 步：aₜ¹ = 去噪一步                   （非常清晰的轨迹）
第 5 步：aₜ⁰ = 去噪最后一步               （最终输出的动作轨迹！）
```

用 DPM-Solver++ 加速器，**只需要 5 步**就能从噪声变成高质量动作（比原始 DDPM 的 1000 步快 200 倍）。

### 为什么用 DiT 而不是普通 Transformer？

RDT 用的是 DiT（Diffusion Transformer），和普通 Transformer 有三个关键区别：

#### 区别一：QKNorm + RMSNorm

```python
# 普通 Transformer
output = softmax(Q @ K.T / sqrt(d)) @ V  # 可能数值爆炸

# RDT 的 DiT
Q = rmsnorm(Q)  # 归一化
K = rmsnorm(K)  # 归一化
output = softmax(Q @ K.T / sqrt(d)) @ V  # 稳定
```

为什么？机器人动作是**时间序列**，Token 之间的对称性很重要。普通 LayerNorm 会破坏这种对称性，导致大规模预训练时数值爆炸。RMSNorm 不做中心化，保留了时间序列的对称结构。

#### 区别二：MLP 解码器

```python
# 普通 DiT：最后用线性层
output = linear(latent)  # 线性投影

# RDT：最后用 MLP
output = mlp(latent)     # 非线性投影
```

为什么？机器人动力学是**非线性**的（关节角度 → 末端位置不是线性关系）。线性层无法捕捉这种非线性，MLP 可以。消融实验显示：去掉 MLP 解码器，灵巧操作任务成功率暴跌。

#### 区别三：交替条件注入（ACI）

```python
# 普通 DiT：所有条件一起注入
tokens = concat([image_tokens, text_tokens, noisy_action])

# RDT：交替注入
for layer in layers:
    if layer % 2 == 0:
        tokens = cross_attention(tokens, image_tokens)  # 偶数层注入图像
    else:
        tokens = cross_attention(tokens, text_tokens)   # 奇数层注入文本
```

为什么？图像 token 远多于文本 token（3 张图 × 196 patch = 588 token vs 文本 ~20 token）。如果同时注入，图像会"淹没"文本信息。交替注入让每种模态都有独立的交互窗口。

### 统一动作空间（PIUAS）：让不同机器人"说同一种语言"

这是 RDT 最巧妙的设计之一。

**问题**：46 个数据集来自不同机器人——有的是 6 自由度机械臂，有的是 7 自由度，有的是双臂，有的是单臂。它们的动作格式完全不同。

**解法**：设计一个 **128 维的统一向量**，每个维度有固定的物理含义：

```
[0, 10)    右臂关节位置（10 个关节）
[10, 15)   右夹爪关节位置
[15, 25)   右臂关节速度
[25, 30)   右夹爪关节速度
[30, 33)   右末端执行器位置 (x,y,z)
[33, 39)   右末端执行器 6D 姿态
[39, 42)   右末端执行器速度
...
[50, 60)   左臂关节位置
[60, 65)   左夹爪关节位置
...
[100, 103) 底座线速度/角速度
[103, 128) 预留
```

每个机器人把自己的动作"映射"到这个统一空间：
- 7 自由度双臂：填满左右臂各 7 个关节位置
- 6 自由度单臂：填右臂前 6 个位置，其余补零
- 移动机器人：额外填底座速度

**好处**：
1. 不同机器人可以共享同一个模型
2. 每个维度有物理含义——模型能学到"关节角度变化 → 末端移动"这种可迁移的物理规律
3. 未使用的维度补零，不引入噪声

## RDT-2：从"会操作"到"跨具身零样本"

### RDT-1B 的局限

RDT-1B 虽然强，但有三个问题：

1. **推理太慢**：5 步去噪对实时控制（如打乒乓球）来说还是太慢
2. **不能跨具身**：训练时用的机器人和部署时必须一样
3. **语言理解有限**：用冻结的 T5 编码语言，不能理解复杂指令

RDT-2 的解法：**用 7B VLM 替换自研骨干 + Flow Matching 替换 DDPM + 三阶段训练**。

### 架构：7B VLM + 400M 动作专家

```
RDT-1B：  自研 DiT（1.2B）= 感知 + 理解 + 动作生成（全在一个模型里）

RDT-2：   Qwen2.5-VL（7B）= 感知 + 理解（冻结）
          + 动作专家（400M）= 动作生成（可训练）
          两个模型分工明确
```

| | RDT-1B | RDT-2 |
|---|---|---|
| 骨干 | 自研 DiT 1.2B | Qwen2.5-VL 7B（冻结） |
| 动作生成 | DiT 自己做 | 独立动作专家 400M |
| 语言理解 | T5-XXL（冻结） | Qwen2.5-VL 原生（强得多） |
| 注意力 | Multi-Head Attention | **GQA**（Grouped Query Attention，更快） |

### 核心创新一：RVQ——把连续动作变成离散 token

这是 RDT-2 最关键的设计——**用残差向量量化（RVQ）桥接语言和动作**。

**问题**：VLM（如 Qwen）处理的是**离散 token**（文字），扩散模型处理的是**连续向量**（动作）。两者格式不兼容。

**解法**：用 RVQ 把连续动作编码成离散 token，让 VLM 能"看懂"动作。

#### RVQ 的工作原理

```
连续动作 A_t ∈ R^{64×14}（64 步 × 14 维）
    ↓ 1D 时序 CNN 编码器
潜在向量 z₁, z₂, ..., zₙ ∈ R^C
    ↓ 多级量化（m=8 级）
每一级用一个 codebook（码本）量化：
  第 1 级：找最近的码字 e₁(k₁)，算残差 r₁ = z - e₁(k₁)
  第 2 级：对残差再量化，找最近的码字 e₂(k₂)，算残差 r₂ = r₁ - e₂(k₂)
  ...
  第 m 级：对残差再量化
    ↓ 输出
离散 token 序列：{k₁, k₂, ..., kₘ}（每个潜在向量 m 个 token）
```

**为什么用 RVQ 而不是普通 VQ？**

| 方法 | 同等量化误差需要的 token 数 | 效率 |
|------|--------------------------|------|
| 均匀量化 | 很多（效率低） | x |
| FAST tokenizer（pi0 用的） | 3x | 中等 |
| **RVQ** | **1x**（最少） | o |

RVQ 通过"残差逐级细化"，用最少的 token 达到最低的量化误差。

#### RVQ 如何桥接语言和动作？

```
Stage 1：训练 VLM 理解动作
  语言指令 token + 图像 token + RVQ 动作 token → VLM → 下一个 token 预测（CE loss）
  → VLM 学会了"给定语言和图像，动作 token 应该是什么"

Stage 2：训练动作专家生成动作
  VLM 输出的特征 → 动作专家 → Flow Matching → 连续动作
  → 动作专家学会了"从 VLM 的理解中生成精确的连续动作"
```

**关键洞察**：VLM 不直接生成动作，而是提供"理解"；动作专家不理解语义，只负责"执行"。分工明确。

### 核心创新二：Flow Matching 替换 DDPM

RDT-2 用 Flow Matching 替换了 RDT-1B 的 DDPM，效率大幅提升。

#### 为什么 Flow Matching 更好？

| | DDPM（RDT-1B） | Flow Matching（RDT-2） |
|---|---|---|
| 训练目标 | 预测噪声 | 预测速度场 u = A_t - epsilon |
| 路径 | 弯路（逐步加噪再去噪） | **直线**（从噪声直走到动作） |
| 推理步数 | 5 步（DPM-Solver++） | **5 步**（Euler 积分） |
| 训练收敛 | 较慢 | **更快**（更直接的梯度信号） |
| 与 VLM 兼容 | 需要额外适配 | **天然兼容**（线性插值更简单） |

#### Flow Matching 在 RDT-2 中的具体实现

**训练时**：

$$A_t^\tau = (1-\tau)\varepsilon + \tau \cdot A_t$$

$$\mathcal{L}_{\text{expert}} = \mathbb{E}\Big[\big\| v_\theta(\tau, A_t^\tau, \text{VLA}(\ell, o_t)) - (A_t - \varepsilon) \big\|^2\Big]$$

翻译：
- $\tau \in [0, 1]$：流时间（$\tau=0$ 是噪声，$\tau=1$ 是真实动作）
- $A_t^\tau$：在 $\tau$ 时刻的插值动作
- $v_\theta$：动作专家网络，预测速度场
- 正确答案：$A_t - \varepsilon$（从噪声指向真实动作的方向）

**推理时**：

```
A_t^0 ~ N(0, I)           （纯噪声）
for tau in [0, 0.2, 0.4, 0.6, 0.8]:
    v = v_theta(tau, A_t^tau, VLA(l, o_t))   （预测速度）
    A_t^{tau+0.2} = A_t^tau + 0.2 x v     （走一步）
A_t^1 = 最终输出的动作轨迹
```

**VLA 骨干只算一次**：在整个 5 步积分过程中，Qwen2.5-VL 的输出不变——只需要编码一次图像和语言，5 步积分只跑轻量的动作专家（400M），非常快。

### 核心创新三：三阶段训练配方

```
Stage 1：RVQ 预训练（128K 步）
  目标：让 VLM 学会"理解"动作
  方法：连续动作 → RVQ 编码 → 离散 token → VLM 下一个 token 预测（CE loss）
  冻结：无（VLM 和 RVQ 编码器都训练）
  关键：保留了 VLM 预训练的离散概率知识

Stage 2：Flow Matching 微调（66K 步）
  目标：让动作专家学会"生成"连续动作
  方法：冻结 VLM，训练动作专家（400M）用 Flow Matching
  冻结：VLM 骨干
  关键：VLM 的理解能力不被破坏，动作专家只学"执行"

Stage 3：蒸馏（单步生成）
  目标：把 5 步去噪蒸馏成 1 步生成
  方法：教师 = 5 步 Flow Matching，学生 = 1 步直接生成
  损失：学生输出 vs 教师输出的 MSE
  关键：实时推理成为可能（打乒乓球等高速任务）
```

#### 为什么需要三阶段？直接端到端不行吗？

**如果直接在 VLM 上做扩散**：扩散过程的噪声会**破坏 VLM 预训练的离散知识**——VLM 被训练来处理清晰的离散 token，给它加噪声会让它"忘记"语言理解能力。

**三阶段的精妙之处**：
1. Stage 1 用 RVQ 把动作变成离散 token → VLM 用它熟悉的方式（CE loss）学习动作
2. Stage 2 冻结 VLM → 扩散过程只影响动作专家，不破坏 VLM
3. Stage 3 蒸馏 → 把多步采样压缩成单步，不改变模型能力

### 跨具身零样本泛化：4U 设置

RDT-2 实现了**四个维度同时零样本泛化**：

| 维度 | 含义 | 怎么做到的 |
|------|------|----------|
| **Unseen Embodiment** | 从未见过的机器人 | UMI 是具身无关的——记录的是末端执行器位姿，不是关节角度 |
| **Unseen Scene** | 从未见过的场景 | 大规模数据覆盖 100+ 家庭环境 |

## 深度拆解：RVQ、DiT、GQA、PIUAS、π0 对比等核心概念全讲透

> 这一节专门回答常见困惑，每个概念都从"它到底是什么"讲起，配合流程图和伪代码。

### 一、RVQ 到底在干嘛？——为什么 Flow Matching 能直接输出连续动作，还要搞离散 token？

这是最核心的困惑。先说结论：

> **Flow Matching 确实能直接输出连续动作序列。RVQ 不是给 Flow Matching 用的，而是给 VLM 用的。**

#### 问题的根源：VLM 和动作专家"说不同的语言"

```
VLM（Qwen2.5-VL）：
  输入：离散 token（文字）→ 输出：离散 token（下一个词的概率分布）
  它天生只会处理和生成离散 token

动作专家（Action Expert）：
  输入：连续向量 → 输出：连续动作序列
  它需要的是连续特征，不是离散 token

问题：VLM 的输出怎么喂给动作专家？
  VLM 输出 → ??? → 动作专家输入
  离散 token → ??? → 连续向量
```

**RVQ 就是这个"翻译官"**——它让 VLM 能"理解"动作，同时让动作专家能"接收" VLM 的理解。

#### RVQ 的完整工作流程

```
========== 编码阶段（训练时 + 推理时）==========

连续动作 A_t ∈ R^{64×14}（64 个时间步 × 14 维动作）
  ↓
1D 时序 CNN 编码器（把时间序列压缩成单个向量）
  ↓
潜在向量 z ∈ R^C（C=512，一个紧凑的连续向量）
  ↓
多级残差量化（m=8 级，每级一个码本 codebook）

第 1 级量化：
  码本 C₁ = {e₁¹, e₁², ..., e₁^K}（K=1024 个码字）
  找 z 最近的码字：k₁ = argmin_k ‖z - e₁ᵏ‖
  量化结果：ẑ₁ = e₁ᵏ¹
  残差：r₁ = z - ẑ₁

第 2 级量化：
  码本 C₂ = {e₂¹, e₂², ..., e₂^K}
  找 r₁ 最近的码字：k₂ = argmin_k ‖r₁ - e₂ᵏ‖
  量化结果：ẑ₂ = e₂ᵏ²
  残差：r₂ = r₁ - ẑ₂

... 重复 8 级 ...

第 8 级量化：
  码本 C₈
  找 r₇ 最近的码字：k₈ = argmin_k ‖r₇ - e₈ᵏ‖

输出：离散 token 序列 {k₁, k₂, ..., k₈}（8 个整数）
重建：ẑ = ẑ₁ + ẑ₂ + ... + ẑ₈ ≈ z（8 级残差累加接近原始向量）
```

#### 为什么用 RVQ 而不是普通 VQ？

**普通 VQ（向量量化）**：

```
z ∈ R^512 → 码本 C = {e¹, e², ..., e^K} → 找最近的码字 → 输出 1 个 token

问题：一个 512 维的向量用 1 个码字表示？
  → 码本需要超级大（K 要非常大才能覆盖所有可能的 z）
  → 或者量化误差超级大（K 不够大时，z 和最近码字差距很大）
```

**RVQ（残差向量量化）**：

```
z ∈ R^512 → 第 1 级量化 → 残差 r₁ → 第 2 级量化 → 残差 r₂ → ... → 第 8 级

效果：8 个小码本（每个 K=1024）级联，等效一个超大码本（K^8 = 1024^8 ≈ 10^24 个组合）
  → 量化精度极高
  → 每级只增加 1 个 token，总共只用 8 个 token
```

**类比**：

```
普通 VQ：用 1 个数字描述一个人的身高 → 要么很粗（170cm、180cm 两档）
RVQ：用 8 个数字描述 → "身高 175cm + 体重 70kg + ..." → 描述更精确
每一级都在修正上一级的"误差"
```

#### RVQ vs FAST tokenizer（π₀ 用的）

| | RVQ（RDT-2） | FAST tokenizer（π₀） |
|---|---|---|
| **量化方式** | 残差逐级细化（8 级） | 均匀分桶 |
| **每个时间步需要的 token 数** | 8 个 | 24 个（3× 更多） |
| **量化精度** | 高（残差累积逼近原值） | 中（分桶粒度有限） |
| **码本大小** | 8 × 1024 = 8K | 24 × 8192 = 192K |
| **训练方式** | EMA 更新码本 + 路径直通估计 | 同上 |
| **为什么选它** | token 少 → VLM 处理快 | 实现简单 |

#### 为什么不用 Flow Matching 直接输出连续动作，非要加 RVQ？

**核心原因：VLM 需要离散 token 才能"理解"动作。**

```
方案 A：不用 RVQ，直接让 VLM 输出连续向量
  VLM 输出 → 线性层 → 连续向量 → 动作专家

  问题：
  1. VLM 是用下一个 token 预测（CE loss）训练的，输出是概率分布 over 离散词表
  2. 强行加线性层输出连续向量 → VLM 无法用它熟悉的 CE loss 学习
  3. VLM 预训练的离散知识全部浪费
  4. 训练不稳定，效果差

方案 B：用 RVQ（RDT-2 的做法）
  连续动作 → RVQ 编码 → 离散 token → VLM 用 CE loss 学习 → VLM 输出特征 → 动作专家 → FM → 连续动作

  优点：
  1. VLM 用它最熟悉的方式（CE loss over 离散 token）学习动作
  2. VLM 预训练的离散概率知识完整保留
  3. 训练稳定，收敛快
  4. VLM 理解动作后，输出的特征向量语义丰富
```

**方案 C：π₀ 的做法（不用 RVQ）**

```
π₀ 的做法：
  VLM（PaliGemma）→ 输出连续特征 → 直接喂给 Flow Matching 动作头
  不做离散化，VLM 直接在连续空间操作

  代价：
  1. VLM 需要额外训练来适应连续输出（破坏部分预训练知识）
  2. 需要更多数据来弥补知识损失
  3. 但好处是架构更简单，不需要 RVQ 编解码器
```

#### RVQ 在 RDT-2 完整 pipeline 中的位置

```
========== 训练 Stage 1：RVQ 预训练 ==========

输入：
  图像 o_t → Qwen2.5-VL 编码 → 图像 token
  语言指令 ℓ → Qwen2.5-VL 编码 → 语言 token
  连续动作 A_t → RVQ 编码 → 离散 token {k₁, k₂, ..., k₈}

训练目标：
  VLM 输入：[图像 token, 语言 token, RVQ 动作 token₁, ..., RVQ 动作 token₇]
  VLM 输出：预测 RVQ 动作 token₈（下一个 token 预测）
  Loss：Cross-Entropy（VLM 预测的 token 分布 vs 真实 token）

效果：
  VLM 学会了"给定图像和语言，动作的 RVQ token 应该是什么"
  → VLM "理解"了动作的语义

========== 训练 Stage 2：Flow Matching ==========

输入：
  图像 o_t → 冻结的 Qwen2.5-VL → 特征向量 h_t
  连续动作 A_t（真实值）

训练目标：
  动作专家输入：(h_t, A_t^τ, τ)  ← VLM 的特征 + 加噪动作 + 时间步
  动作专家输出：预测速度场 v_θ
  Loss：MSE(v_θ, A_t - ε)

效果：
  动作专家学会了"从 VLM 的理解中生成精确的连续动作"

========== 推理时 ==========

输入：图像 + 语言指令

第 1 步：VLM 编码
  图像 + 语言 → Qwen2.5-VL → 特征向量 h_t（只算一次）

第 2 步：Flow Matching 采样（5 步或 1 步蒸馏）
  A_t^0 ~ N(0, I)
  for τ in [0, 0.2, 0.4, 0.6, 0.8]:
      v = 动作专家(τ, A_t^τ, h_t)
      A_t^{τ+0.2} = A_t^τ + 0.2 × v

输出：A_t^1 = 最终的连续动作序列（64 步 × 14 维）

注意：推理时完全不需要 RVQ！RVQ 只在训练 Stage 1 用。
推理时 VLM 直接输出特征向量 h_t，动作专家直接从 h_t 生成连续动作。
```

#### 一句话总结 RVQ 的作用

> **RVQ 是训练时的"桥梁"：把连续动作变成离散 token，让 VLM 用它熟悉的方式（CE loss）学会理解动作。推理时不需要 RVQ——VLM 直接输出特征向量，动作专家直接生成连续动作。**

### 二、DiT vs 普通 Transformer：架构到底有什么区别？

DiT（Diffusion Transformer）不是"发明了一种新 Transformer"，而是在标准 Transformer 基础上做了**三处关键修改**，让它特别适合做扩散模型的骨干网络。

#### 完整架构对比

```
========== 普通 Transformer（如 GPT-2）==========

输入 token → Embedding → 位置编码
  ↓
Transformer Block × N：
  LayerNorm → Multi-Head Self-Attention → 残差连接
  LayerNorm → FFN (Linear → GELU → Linear) → 残差连接
  ↓
LayerNorm → Linear → 输出 logits

特点：
  - 用 LayerNorm（做中心化：减均值除标准差）
  - 线性层输出
  - 位置编码通常是固定的正弦编码或可学习的

========== DiT（RDT-1B 用的）==========

输入 token（含噪声动作）→ Patchify + Embedding → 位置编码
  ↓
DiT Block × 28 层：
  QKNorm + RMSNorm → Multi-Head Self-Attention → 残差连接
  QKNorm + RMSNorm → FFN (Linear → SiLU → Linear) → 残差连接
  + Adaptive normalization（时间步 + 条件注入）
  ↓
MLP 解码器（Linear → SiLU → Linear → Linear）→ 输出噪声预测

特点：
  - 用 RMSNorm（不做中心化，只做缩放）
  - QKNorm（对 Q 和 K 做归一化，防止注意力分数爆炸）
  - MLP 解码器（非线性投影，不是线性层）
  - Adaptive normalization（把时间步和条件信息注入每一层）
```

#### 三处关键修改的详细解释

**修改一：RMSNorm 替换 LayerNorm**

```python
# LayerNorm（普通 Transformer）
def layer_norm(x):
    mean = x.mean(dim=-1, keepdim=True)
    std = x.std(dim=-1, keepdim=True)
    return (x - mean) / (std + eps)  # 中心化 + 缩放

# RMSNorm（DiT）
def rms_norm(x):
    rms = x.pow(2).mean(dim=-1, keepdim=True).sqrt()
    return x / (rms + eps)  # 只缩放，不中心化
```

为什么？机器人动作是**时间序列**，token 之间的相对位置关系很重要。LayerNorm 会把每个 token 的均值减掉，破坏了"这个 token 比那个 token 大多少"的相对关系。RMSNorm 不减均值，保留了这种对称性。

**修改二：QKNorm（Query-Key Normalization）**

```python
# 普通 Transformer 的注意力
Q = x @ W_Q  # 可能值很大
K = x @ W_K  # 可能值很大
attn = softmax(Q @ K.T / sqrt(d))  # Q @ K.T 可能爆炸 → softmax 饱和 → 梯度消失

# DiT 的注意力
Q = rms_norm(x @ W_Q)  # 归一化到合理范围
K = rms_norm(x @ W_K)  # 归一化到合理范围
attn = softmax(Q @ K.T / sqrt(d))  # 数值稳定
```

为什么？扩散模型在去噪过程中，噪声大小从 0 到 1 变化很大。如果不做 QKNorm，注意力分数会随噪声大小剧烈波动，训练不稳定。QKNorm 保证注意力分数始终在合理范围内。

**修改三：MLP 解码器替换线性层**

```python
# 普通 DiT / Transformer：最后用线性层
output = linear(transformer_output)  # 线性投影：y = Wx + b

# RDT 的 DiT：最后用 MLP
h = silu(linear1(transformer_output))  # 第一层：y₁ = SiLU(W₁x + b₁)
output = linear2(h)                     # 第二层：y₂ = W₂y₁ + b₂
```

为什么？机器人动力学是**高度非线性**的：

```
关节角度 θ → 末端位置 (x, y, z)

这不是线性关系！
  θ = 0° → 末端在 (0.5, 0, 0.3)
  θ = 90° → 末端在 (0, 0, 0.8)
  θ = 180° → 末端在 (-0.5, 0, 0.3)

线性层学不了这种非线性映射。
MLP（带 SiLU 激活函数）可以。
```

消融实验验证：去掉 MLP 解码器，换成线性层，灵巧操作（如拧瓶盖）的成功率从 62.5% 暴跌到 25%。

#### DiT 的 Adaptive Normalization：条件注入的机制

DiT 有一个普通 Transformer 没有的东西——**Adaptive Normalization**（自适应归一化）：

```python
# 普通 Transformer：条件信息通过注意力注入
# 所有条件（图像、文本、时间步）都 concat 成 token 序列

# DiT：条件信息通过归一化层注入
def adaptive_norm(x, condition):
    # condition 包含时间步 t 和语言/图像信息
    gamma, beta = mlp(condition).chunk(2, dim=-1)  # 从条件生成缩放和偏移
    return rms_norm(x) * (1 + gamma) + beta  # 缩放 + 偏移

# 在每个 DiT Block 中：
x = x + self_attn(adaptive_norm(x, condition))
x = x + ffn(adaptive_norm(x, condition))
```

为什么？扩散模型需要知道"当前在去噪的第几步"。这个时间步信息通过 Adaptive Normalization 注入每一层，而不是通过注意力。这样时间步信息能直接影响每一层的特征分布，而不仅仅是"参与计算"。

---

### 三、GQA vs MHA：注意力机制的区别

这是 RDT-1B 和 RDT-2 在骨干网络层面的核心区别之一。

#### MHA（Multi-Head Attention）—— RDT-1B 用的

```
输入 x ∈ R^{seq_len × d_model}
  ↓
Q = x @ W_Q  →  (seq_len, d_model)  →  拆成 h 个头 → 每个头 (seq_len, d_k)
K = x @ W_K  →  同上
V = x @ W_V  →  同上

每个头独立做注意力：
  head_i = softmax(Q_i @ K_i.T / sqrt(d_k)) @ V_i

所有头拼接：
  output = concat(head_1, ..., head_h) @ W_O

参数量：
  W_Q, W_K, W_V, W_O 各 (d_model × d_model)
  总共 4 × d_model² 个参数
```

#### GQA（Grouped Query Attention）—— RDT-2 用的

```
输入 x ∈ R^{seq_len × d_model}
  ↓
Q = x @ W_Q  →  (seq_len, d_model)  →  拆成 h 个头
K = x @ W_K  →  (seq_len, d_k)      →  拆成 g 个头（g < h）
V = x @ W_V  →  (seq_len, d_v)      →  拆成 g 个头

关键区别：Q 有 h 个头，但 K 和 V 只有 g 个头
  → 每 g/h 个 Q 头共享一组 K、V 头

例如 h=32, g=8：
  Q 头 0,1,2,3 共享 K 头 0 和 V 头 0
  Q 头 4,5,6,7 共享 K 头 1 和 V 头 1
  ...

参数量：
  W_Q: (d_model × d_model)
  W_K: (d_model × d_k × g)  ← g < h，所以更小
  W_V: (d_model × d_v × g)  ← 同上
  W_O: (d_model × d_model)
  总共大约 4 × d_model² × (1 - h/g 的比例减少)
```

#### 直观理解

```
MHA：每个注意力头都有自己的 Q、K、V → 每个头能"独立关注"不同的模式
  → 表达能力强
  → 但计算量大（每个头都要算 K、V）

GQA：多个 Q 头共享 K、V → 减少 K、V 的计算量
  → 表达能力略弱（K、V 的多样性减少）
  → 但计算快很多（K、V 只算 g 次而不是 h 次）

类比：
  MHA = 32 个人各自独立做 PPT，每人做一套
  GQA = 32 个人分 8 组，每组共用一套 PPT，各自做自己的演讲
```

#### 为什么 RDT-2 选 GQA？

| | MHA（RDT-1B） | GQA（RDT-2） |
|---|---|---|
| **KV 缓存** | 大（每个头一组 KV） | 小（g 组 KV） |
| **推理速度** | 慢 | **快 30-50%** |
| **显存占用** | 高 | **低** |
| **表达能力** | 强 | 略弱，但够用 |
| **适用场景** | 模型小（1.2B），不需要极致优化 | 模型大（7B），需要控制计算量 |

RDT-2 用 7B 的 Qwen2.5-VL，如果用 MHA，KV 缓存会非常大。GQA 把 KV 头从 32 个减到 8 个，推理时省了 75% 的 KV 缓存，速度提升明显。

### 四、统一动作空间（PIUAS）：到底是什么？

你说得对——PIUAS 本质上就是**"动作分桶分区间"**。但它的设计比简单的分桶更巧妙。

#### 简单分桶 vs PIUAS

```
简单分桶（如 Octo）：
  把每个动作维度的值域分成 256 个桶
  动作值 0.5 → 桶编号 128
  问题：
  1. 不同机器人的动作维度含义不同（一个机器人的"关节 1"和另一个的"关节 1"不一样）
  2. 桶编号没有物理含义（128 代表什么？不知道）
  3. 跨机器人迁移时，桶编号对不上

PIUAS（RDT-1B）：
  不是分桶，而是定义一个 128 维的"通用语言"
  每个维度有固定的物理含义：
    维度 0 = 右臂关节 1 的角度（弧度）
    维度 1 = 右臂关节 2 的角度
    ...
    维度 30 = 右末端执行器 x 坐标
    维度 31 = 右末端执行器 y 坐标
    ...

  每个机器人把自己的动作"翻译"成这个通用语言：
    7-DoF 双臂机器人：
      维度 [0,7) → 填右臂 7 个关节角度
      维度 [50,57) → 填左臂 7 个关节角度
      其余维度补零

    6-DoF 单臂机器人：
      维度 [0,6) → 填右臂 6 个关节角度
      维度 [30,33) → 填末端执行器位置
      其余维度补零
```

#### PIUAS 的完整维度定义

```
维度 [0, 10)   → 右臂关节位置（最多 10 个关节）
维度 [10, 15)  → 右夹爪关节位置
维度 [15, 25)  → 右臂关节速度
维度 [25, 30)  → 右夹爪关节速度
维度 [30, 33)  → 右末端执行器位置 (x, y, z)
维度 [33, 39)  → 右末端执行器 6D 姿态（轴角或四元数）
维度 [39, 42)  → 右末端执行器线速度 (vx, vy, vz)
维度 [42, 45)  → 右末端执行器角速度
维度 [45, 50)  → 预留

维度 [50, 60)  → 左臂关节位置
维度 [60, 65)  → 左夹爪关节位置
维度 [65, 75)  → 左臂关节速度
维度 [75, 80)  → 左夹爪关节速度
维度 [80, 83)  → 左末端执行器位置
维度 [83, 89)  → 左末端执行器 6D 姿态
维度 [89, 92)  → 左末端执行器线速度
维度 [92, 95)  → 左末端执行器角速度
维度 [95, 100) → 预留

维度 [100, 103) → 底座线速度 (vx, vy) + 角速度 (ωz)
维度 [103, 128) → 预留
```

#### 为什么 PIUAS 比简单分桶好？

| | 简单分桶 | PIUAS |
|---|---|---|
| **维度含义** | 无（桶编号 128 是什么？） | **有**（维度 30 = 右末端 x 坐标） |
| **跨机器人** | 桶编号对不上，不能共享模型 | 维度对齐，可以共享模型 |
| **物理规律** | 模型需要重新学习 | 模型能学到"维度 0 变化 → 维度 30 变化"的物理规律 |
| **未使用维度** | 不确定填什么 | 补零，明确无歧义 |

**核心insight**：PIUAS 让不同机器人的动作"说同一种语言"。模型在预训练时学到了"关节角度变化 → 末端位置变化"这种**可迁移的物理规律**，而不是"这个机器人的编号 128 对应那个机器人的编号 256"这种不可迁移的映射。

### 五、UMI 和 4U 到底是什么？

#### UMI（Universal Manipulation Interface）

UMI 是斯坦福 Qiuyuan（Chi）团队在 2024 年提出的一个**数据采集接口**，核心思想是：

> **不记录机器人的关节角度，而是记录末端执行器的位姿。**

```
传统数据采集：
  机器人执行任务 → 记录每个时刻的关节角度 θ₁, θ₂, ..., θ₇
  问题：不同机器人的关节角度含义不同，数据不能跨机器人复用

UMI 数据采集：
  人手持 UMI 设备（带相机 + IMU）执行任务
  → 记录 6-DoF 末端执行器位姿 (x, y, z, rx, ry, rz) + 夹爪宽度
  → 不记录任何关节角度

为什么？
  末端执行器位姿是"具身无关"的——不管用什么机器人，末端执行器的位置和姿态是同一个物理量
  关节角度是"具身相关"的——不同机器人的关节定义不同
```

#### UMI 硬件

```
UMI 设备组成：
  1. 相机：Intel RealSense D405（RGB-D）
  2. IMU：惯性测量单元（追踪手持设备的位姿）
  3. 夹爪：平行夹爪（记录开合宽度）
  4. 手持支架：人手握住执行任务

采集流程：
  人手持 UMI → 在真实环境中执行任务（如抓杯子、拧瓶盖）
  → 相机记录视觉观测
  → IMU + 视觉里程计追踪末端执行器位姿
  → 夹爪记录开合宽度
  → 保存：(视觉帧, 末端执行器位姿序列, 夹爪宽度序列)
```

#### 4U（四个 Unseen）

RDT-2 实现了**四个维度同时零样本泛化**：

```
1. Unseen Embodiment（从未见过的机器人）
   训练时用 UMI 采集的数据（手持设备）
   部署时用 Franka 机械臂、UR5 机械臂、甚至自制机器人
   → 因为 UMI 数据是具身无关的，策略可以直接迁移

2. Unseen Scene（从未见过的场景）
   训练数据覆盖 100+ 家庭环境（厨房、客厅、办公室...）
   测试时在全新的环境中运行
   → 大规模数据带来的场景泛化

3. Unseen Object（从未见过的物体）
   训练时没见过的物体（如新品牌的杯子）
   测试时让机器人操作这些新物体
   → VLM 的开放词汇理解能力（"这是一个杯子"→ 知道怎么操作）

4. Unseen Instruction（从未见过的语言指令）
   训练时没见过的指令表述（如"请帮我把那个红色的杯子放到微波炉旁边"）
   测试时用这些新指令
   → VLM 的语言泛化能力
```

#### 为什么 4U 很厉害？

```
以前的方法：
  训练时用 Franka 机器人 → 部署时必须用 Franka
  训练时在厨房采数据 → 在客厅可能不行
  训练时见过马克杯 → 换个纸杯可能不行
  训练时用"拿起杯子" → 说"帮我取一下那个杯子"可能不行

RDT-2 的 4U：
  训练时用 UMI 手持采集 → 部署时可以用任何机器人
  训练时覆盖多种环境 → 新环境也能工作
  VLM 理解语义 → 新物体也能识别
  VLM 理解语言 → 新指令也能理解
```

### 六、π₀ vs RDT-2：到底有什么区别？

很多人觉得 π₀ 和 RDT-2 很像（都是 VLM + 动作专家），但它们在关键设计上有本质区别。

#### 架构对比

```
========== π₀（Physical Intelligence）==========

VLM：PaliGemma（3B，Google 的视觉语言模型）
  → 输入：图像 + 语言指令
  → 输出：连续特征向量（不是离散 token）

动作头：Flow Matching（直接从连续特征生成连续动作）
  → 输入：VLM 的连续特征 + 噪声动作
  → 输出：去噪后的连续动作

动作编码：FAST tokenizer
  → 把连续动作离散化成 24 个 token/时间步
  → 用均匀分桶（不是 RVQ）

训练方式：
  Stage 1：VLM + FAST tokenizer 预训练（让 VLM 理解动作）
  Stage 2：Flow Matching 微调（训练动作头）

特点：
  - VLM 直接输出连续特征（不经过离散 token）
  - FAST tokenizer 只在预训练 Stage 1 用
  - 推理时不需要离散化

========== RDT-2（清华）==========

VLM：Qwen2.5-VL（7B，阿里 的视觉语言模型）
  → 输入：图像 + 语言指令
  → 输出：连续特征向量（Stage 2 之后）

动作专家：Flow Matching
  → 输入：VLM 的连续特征 + 噪声动作
  → 输出：去噪后的连续动作

动作编码：RVQ
  → 把连续动作离散化成 8 个 token/时间步
  → 用残差量化（比 FAST 更高效）

训练方式：
  Stage 1：RVQ 预训练（让 VLM 用 CE loss 理解动作）
  Stage 2：Flow Matching 微调（冻结 VLM，训练动作专家）
  Stage 3：蒸馏（5 步 → 1 步）

特点：
  - VLM 在 Stage 1 用离散 token 学习，Stage 2 输出连续特征
  - RVQ 比 FAST 更高效（8 token vs 24 token）
  - 三阶段训练更精细
  - 有蒸馏步骤（π₀ 没有）
```

#### 核心区别对比表

| 维度 | π₀ | RDT-2 |
|------|-----|-------|
| **VLM** | PaliGemma 3B | Qwen2.5-VL 7B |
| **动作编码** | FAST tokenizer（均匀分桶，24 token/步） | RVQ（残差量化，8 token/步） |
| **VLM 如何理解动作** | 直接输出连续特征 | Stage 1 用离散 token CE loss |
| **动作头** | Flow Matching | Flow Matching |
| **训练阶段** | 2 阶段 | **3 阶段**（多一步蒸馏） |
| **推理步数** | 5-10 步 | **1 步**（蒸馏后） |
| **模型大小** | 3B + 动作头 | 7B + 400M |
| **跨具身** | 弱（主要在固定机器人上训练） | **强**（UMI 数据 + 4U 泛化） |
| **关键优势** | 架构简单，端到端 | 三阶段保护 VLM 知识，1 步推理更快 |

#### 为什么它们看起来像但本质不同？

```
表面相似：
  都是 VLM + 动作专家
  都用 Flow Matching 生成动作
  都处理图像和语言

本质区别：
  1. VLM 学习方式不同
     π₀：VLM 直接在连续空间操作，部分牺牲预训练知识
     RDT-2：VLM 用离散 token 学习（Stage 1），完整保留预训练知识

  2. 动作编码效率不同
     π₀：FAST tokenizer，24 token/步
     RDT-2：RVQ，8 token/步（3× 更高效）

  3. 训练配方不同
     π₀：2 阶段
     RDT-2：3 阶段（多一步蒸馏 → 1 步推理）

  4. 泛化能力不同
     π₀：主要在固定机器人上训练，跨具身弱
     RDT-2：UMI 数据 + 4U 泛化，跨具身强
```

### 七、为什么 Flow Matching 能直接输出连续动作，还要 RVQ？——最核心的困惑解答

这个问题值得单独回答，因为它是理解 RDT-2 架构的关键。

#### 先澄清一个误解

> **RVQ 不是在推理时把 Flow Matching 的输出离散化。RVQ 是在训练时让 VLM "理解"动作的工具。**

```
推理时的流程（没有 RVQ！）：
  图像 + 语言 → VLM → 特征向量 h_t
  噪声动作 + h_t → Flow Matching 动作专家 → 连续动作 A_t

  全程连续，没有离散化！
```

#### 那 RVQ 在哪用？

```
RVQ 只在训练 Stage 1 用：

Stage 1 训练时：
  连续动作 A_t → RVQ 编码 → 离散 token {k₁, ..., k₈}
  VLM 输入：[图像 token, 语言 token, RVQ token₁, ..., RVQ token₇]
  VLM 输出：预测 RVQ token₈（CE loss）

  → VLM 学会了"动作的离散表示"

Stage 2 训练时：
  VLM 冻结，不再需要 RVQ
  VLM 输出特征 → 动作专家 → Flow Matching → 连续动作

推理时：
  完全不需要 RVQ
```

#### 为什么不能跳过 Stage 1，直接训练动作专家？

```
方案：不用 RVQ，直接 Stage 2

  VLM（随机初始化输出层）→ 连续特征 → 动作专家 → Flow Matching

  问题：
  1. VLM 的输出层是随机的，输出的特征向量没有语义
  2. 动作专家收到的是"乱码"特征，学不到有意义的东西
  3. 需要海量数据重新训练 VLM 的输出层
  4. VLM 预训练的语言/视觉知识被破坏

用 RVQ 的 Stage 1：
  VLM 用它熟悉的方式（CE loss）学习动作 → 输出的特征有语义
  Stage 2 冻结 VLM → 动作专家收到的是"有语义"的特征
  → 少量数据就能训练好
```

#### 一句话总结

> **RVQ 是训练时的"脚手架"：帮助 VLM 理解动作。房子盖好后（训练完成），脚手架拆掉（推理时不用 RVQ），房子照样站得住（VLM 输出的特征已经有语义了）。**
