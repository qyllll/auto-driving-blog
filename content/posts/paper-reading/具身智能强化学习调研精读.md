## 🧒 小白 5 分钟：具身智能的「强化学习」到底在学什么？

**一句话**：模仿学习（IL）是「看老师做，照着学」；**强化学习（RL）是「自己试，按打分改」**——试错拿奖励（reward），把「怎么做得分高」压进模型。

**奖励从哪来？三条常见路线：**
1. **稀疏任务奖励**：整件事做完 = 1 分，中途 = 0（最真实，也最难学）；
2. **密集跟踪奖励**：给一条参考动作（如人跳舞的动捕），每一步「像不像」都有分（SONIC 走这条，免手工设计奖励）；
3. **过程奖励/评委模型**：用一个模型给中间步骤打分（VLA-RL 用 VLM 当过程奖励模型；ABot-AgentOS 的 LLM-as-Judge 同思路）。

**具身 RL 为什么比下棋难？四个坑：**
- **重置难**：游戏死了按重开；机器人要把碗放回原位才能下一局（真机上这就是人工成本）；
- **奖励稀疏 + 接触物理**：抓歪 1 毫米就失败，信号极稀；
- **sim2real**：仿真里练成的策略，真机摩擦光照一变就废；
- **模型太大不稳**：几 B 的 VLA 直接上在线 RL，训练说崩就崩（iRe-VLA 就是为这个提出的）。

**在 VLA 时代，RL 通常不是从零学**，而是**后训练（post-training）**：SFT 打底 → RL 在交互/评测数据上继续拔高（π\*0.6 的 Recap、ConRFT 的离线+在线两段都是这个配方）。本文接下来按**四条战线**展开：底层运动控制 RL（SONIC）→ VLA 后训练算法谱系 → 工程框架（FluxVLA Engine）→ 仿真 RL 底座（一句带过，详见 Benchmark 篇）。

## 1️⃣ 战线 A：SONIC——把「运动跟踪」练成 RL 基础模型

**一句话定位**：NVIDIA + UT Austin 等（Zhengyi Luo、Ye Yuan…Jim Fan/Yuke Zhu 组），Science Robotics 2026（arXiv 2511.07820）——**用 RL 的运动跟踪任务当「可扩展训练目标」**：动捕数据密集监督 + PPO，免手工奖励工程；沿**参数量（1.2M→42M）、数据（1 亿+帧 / 700 小时动捕）、算力（2.1 万 GPU 时、最多 128 GPU）**三轴 scaling，得到单个通用人形控制器。

### 为什么它算「具身 RL」的样板

- **奖励 = 跟踪参考动作的密集项**（论文奖励表 Tab. S3；明确反对「每个场景手工设计奖励」——跳舞和走路的奖励信号完全不同，手写奖励没法 scaling）；
- **训练算法 = PPO 系**（正文多处提及，动捕参考轨迹提供每个状态的监督）；
- **统一 token 空间**：SMPL 人体动作 → 潜在命令，VR 遥操作、视频动捕、**VLA（GR00T）** 共用同一策略接口——RL 学的不是一个任务，而是一个**「听得懂多种指挥的运动接口」**。

**部署与真机**：Jetson Orin 全板载推理；124 条动作序列真机评测集（Fig. S4）、11kg 重物砸落鲁棒性测试（Fig. S5）——RL 训出的跟踪策略直接上真机 G1。

**生态位**：给「人形全身控制」提供了 RL 版答案；与 IL 保数据（遥操作克隆）互补——跟踪奖励让**海量动捕视频**变成可训练的监督，这是数据侧的 scaling。

## 2️⃣ 战线 B/C：VLA 的 RL 后训练谱系——八种打法

预训练 VLA 是「冻结的通才」，RL 后训练负责让它**在自己的失败上变强**。按「谁来打分、碰不碰环境」分八路（全部为调研后核实的代表作）：

### 2.1 iRe-VLA（2501.16664, ICRA 2025）——RL 与 SFT 交替，专治在线 RL 不稳

核心观察：**几 B 的 VLA 直接上在线 RL，训练严重不稳**。解法是 **RL 段与监督（SFT/专家蒸馏）段迭代交替**：RL 提供探索收益，SFT 把模型拉回稳定流形。仿真两套基准 + 真机验证。这是「大模型 RL 后训练」工程配方的早期标准答案。

### 2.2 VLA-RL（2505.18719, 清华/南洋理工）——轨迹级 RL + 过程奖励模型

把自回归 VLA 的整条轨迹形式化为**多模态多轮对话的轨迹级 RL**；稀疏奖励用**微调 VLM 当机器人过程奖励模型**（伪奖励标注）解决；系统侧给**向量化环境、批量解码、critic 预热**。结果：OpenVLA-7B 在 LIBERO 40 任务上平均 **81.0%**，超 SFT 微调基线 76.5%（四套 90.2/91.8/82.2/59.8）。注意这个数字口径——同为 LIBERO，协议不同勿与[基准篇](/posts/paper-reading/具身仿真Benchmark全精读/)的其他表直接横比。

### 2.3 RLDG（RSS 2025）——RL 当「数据厂」，蒸馏给通才

**每任务先训 RL 专家策略 → 用专家批量采数据 → 再用这些数据微调单个通才策略**（OpenVLA/Octo 等）。与直接 RL 微调通才相比，成功率高 **30–50%**——把「RL 的高上限」和「通才的可部署性」用蒸馏缝合，真机重置成本也被 RL 专家阶段吸收。

### 2.4 ConRFT（RSS 2025）——离线 + 在线两段，一致性策略当桥

**离线段**先用一致性策略（consistency policy）做稳定初始化，**在线段**再用交互数据强化微调；统一的一致性动作表示让两段共享目标。结论强调：**微调预训练 VLA 比从零 RL 强得多**（从零 RL 的样本需求对真机不现实）。

### 2.5 RLVLA 实证研究（rlvla.github.io）——PPO / GRPO / DPO 到底谁有用？

对 OpenVLA+LoRA 做 RL vs SFT 的系统对照：**RL 主要提升执行类泛化（Execution）**，语义泛化中等受益，视觉泛化与 SFT 持平；工程上给出共享 critic 省 45% 显存、加速 53%、VLA warm-up 少 50% 环境步等实用结论——给「该不该上 RL」提供了实证决策树。

### 2.6 π\*0.6 Recap / RL Token（Physical Intelligence, 2025-11 博客）——从经验中学习再蒸馏进通才

与 π0.7 直接相关的官方路线（见 [π0.7 精读](/posts/paper-reading/π0.7精读/)）：用 RL（Recap 算法）在**特定任务上优化鲁棒性与吞吐**，把训练中产生的**经验数据蒸馏回通才模型**——π0.7 能单模型匹敌各任务 RL 专家，靠的正是把这条 RL 管线产出的数据带元数据吃进预训练。**「RL 不直接上机、而是当数据发动机」**的代表打法。

### 2.7 BORA（2605.30226）——离线 token-动作 RL → 真机在线残差

两段式：**离线阶段**用整合 critic（语义锚定 + 时间信用分配 + IQL）在 token-动作空间做离线 RL；**在线阶段**只学**残差策略**修正基础策略——把「离线 RL 的安全」与「在线 RL 的适应」装进灵巧 VLA，真机只需学小残差。

### 2.8 FIND（2609.32069）——真机自主练习的 Agent 化 RL（3 图详解）

**一句话**：让 VLA **自己找自己不会的题**并反复练——场景理解 → 自我练习 → 自评 → 改进的持久工作区闭环；基础策略 π0.5 + **残差离策略 RL**（critic 式修正动作），8 个可逆真机任务上人工评估成功率 **55% → 71.9%**；单次代表 **6 小时**真机自主运行（含人工仅做场景重置的统计，Table II）。

## 3️⃣ 战线 D：FluxVLA Engine——把 RL 之后的一整条工程线标准化

**一句话定位**：LimX Dynamics 等（arXiv 2609.17210, CC BY 4.0，GitHub FluxVLA/FluxVLA）——**不发明新策略，发明接口**：配置驱动地把异构组件（数据、VLA/WAM、动作头、**reward/advantage-weighted 学习**、分布式训练、仿真评测、推理加速、机器人操作器）拼成可复现的 **data-to-deployment** 工作流；**可选 RLinf 集成**把兼容的预训练流匹配策略扩到**在线 RL 后训练**，且保留其原生接口。

### 它在 RL 谱系里的位置

- **C 战线的货架化**：论文训练栈原生支持 **reward- 或 advantage-weighted 目标**（离线 RL 一族的 AWR/IQL 式打法）与世界模型组件；
- **B 战线的可选件**：**RLinf 集成 = 在线 RL 后训练**插槽（flow 策略可插拔接入）；
- 已支持模型家族：**π0、π0.5、GR00T、OpenVLA、SmolVLA、DreamZero、LlavaVLA**；分布式 FSDP/DDP + LoRA；评测覆盖 **LIBERO / RoboCasa GR-1 / RoboTwin / RoboDojo**；推理侧 **RTC（实时分块）** 多路由 + 加速。

左侧模块化四层栈：**数据（data）→ 模型（model）→ 训练（training）→ 推理（inference）**，各层可替换组件按配置组装；右侧是**跨基准平均闭环成功率柱状图**（LIBERO 等，含消融/加速后对比）。读图抓手：这是**「算法货架」**——RL 后训练只是 training 层的一个可换件，选型视角一目了然。

**离线轨迹与在线观测共用**面向模型的变换与归一化——这一点对 RL 至关重要：在线 RL 采的观测和离线演示必须**同一套预处理**，否则 off-policy 数据一进训练就漂。含自动数据生成与质量校验入口（配套 FluxMimir 数据工具）。

## 💡 综合评析：三个判断 + 三个坑

### 三个判断

1. **「密集奖励可 scaling」与「稀疏奖励要靠模型」正在合流**：SONIC 证明密集跟踪奖励能练出基础控制器；VLA 侧则用过程奖励模型/自评给稀疏任务补信号——两边都在把「奖励工程」变成「数据与模型工程」。
2. **真机 RL 的出路是减少人**：FIND 的可逆任务+自主重置、Recap 的「RL 只当数据厂」、BORA 的「在线只学残差」——都是在绕开人工重置与安全这两个最大成本项。
3. **框架层开始收敛**：FluxVLA Engine 这类平台把 reward-weighted、在线 RL、分布式、多榜评测做成可插拔件——与 XPolicyLab（评测接口）合起来，RL 后训练的「可复现性」问题正在被系统解决。

### 三个坑

1. **协议不一致的分数不可横比**（同是 LIBERO，任务子集/输入视角/episode 数都不同）；
2. **sim RL ≠ 真机能力**：仿真奖励塑形在真机常失效——看结果先问战线 A/B/C；
3. **在线 RL 的安全与分布漂移**未被多数论文充分披露（FIND 的 6 小时统计与人工干预列是好样板）。

## ❓ 自测 Q&A

**Q1：SONIC 和 π\*0.6 的 Recap 都叫 RL，差在哪？**  
SONIC 是**底层控制 RL**：奖励=跟踪人动作，直接产出可部署控制器；Recap 是**任务级优化 + 蒸馏**：RL 产出的是**数据与专家**，最后回灌通才模型。一个练「身体」，一个练「经验」。

**Q2：为什么 VLA 不直接从零 RL？**  
样本效率与安全都不可接受——ConRFT 明确实验说明微调预训练 VLA 远优于从零 RL；通用配方是 SFT 打底再 RL。

**Q3：离线 RL 在具身里怎么用？**  
离线轨迹 + 打分（IQL/AWR 式 advantage-weighted）先吃免费数据（BORA 前半段、FluxVLA 默认能力），需要适应时再上小规模在线或残差段。

**Q4：想复现一条真机 RL 线，最短路径？**  
仿真底座用 Isaac Lab/ManiSkill（PPO/SAC）或 FluxVLA Engine 跑通闭环 → 离线 advantage-weighted 起步 → 有安全重置条件再上 FIND 式自主在线；VLA 主干优先考虑带稳定化设计的（iRe-VLA 交替式）。

**Q5：奖励模型（PRM/Judge）靠谱吗？**  
VLA-RL 用伪标注微调 VLM 做过程奖励拿到 +4.5pp 级收益，但奖励模型误差会直接变成策略漏洞——需配验证器与人工抽检（参考 ABot-AgentOS 三阶段验证思路）。
